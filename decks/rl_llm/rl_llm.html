Preference-based fine-tuning

Motivations

Why do we need a second stage of fine-tuning?

  • Supervised fine-tuning alone cannot guarantee outputs that are fully aligned with human preferences.
  • Collecting larger, high-quality human-labeled datasets is too expensive or impractical.

Preference-based fine-tuning only asks humans to compare model outputs (which answer is better?) instead of writing ideal answers → much cheaper.

So, why do we need a second stage of fine-tuning? Mainly for two reasons: - As I already mentioned, the first reason is that supervised fine-tuning alone cannot guarantee outputs that are fully aligned with human preferences - And the second reason is the lack of high-quality labeled datasets to further improve alignment. Preference-based fine-tuning uses another kind of human feedback: instead of writing the ideal answer, the annotator only compares several answers generated by the model and says which one is better. This is much cheaper and faster, and it also works when people can recognize a good answer more easily than they can write one.

Learn from feedback

A generalization of the RL framework

  • RL agents need feedback to learn preferred behaviors
  • Usually provided by a reward function (maps states/actions to scalar values)
  • Explicit reward functions can be hard to design in real-world tasks
  • Alternative feedback sources (e.g., human preferences, demonstrations) can guide learning
  • This generalizes RL to "learning from feedback"
Training an RL agent requires some information to indicate what behaviors are preferred. This is typically provided by a reward function that maps states and actions to scalar values. However, in some real-world scenarios, designing an explicit reward function is challenging or infeasible. In such cases, we can use other kinds of feedback to guide the learning process. This leads to a generalization of the RL framework called "learning from feedback".

Reward Model

A quick introduction

  • When a reward function is unavailable, we may learn a reward model from data (e.g., expert demonstrations, human preferences).
  • Use the reward model’s output as reward signals for RL algorithms.
  • Learning it from expert demonstrations is known as Inverse Reinforcement Learning (IRL).
  • IRL will be covered in more detail next week.
For the tasks that the reward function is not available, we may consider learning a reward model and then apply the output of this reward model as reward signals on the RL algorithms. In other words, we learn the reward function from data. When this data consists of examples of desired behavior (expert demonstrations), this is called Inverse Reinforcement Learning (IRL) (more on that next week). In the next slides, the reward model will be learned from another kind of data: human preferences.

PbRL: Preference-based RL

Key Idea:

  • Instead of scalar rewards, use preferences over trajectory segments as feedback.
  • Train a reward model to predict which segment is preferred.
  • Use the learned reward model to provide reward signals for RL algorithms.
  • Enables learning from comparative feedback rather than absolute rewards.

👉 When the environment does not provide a reward function, but a preference feedback, we do Preference-based RL (PbRL).

One example of feedback different from scalar rewards is preferences. Preferences can be collected by asking humans to compare pairs of trajectory segments and indicate which one they prefer.

Reinforcement Learning from Human Feedback (RLHF)

  • RLHF introduced by OpenAI and DeepMind (2017) for simulated robots and Atari games.
  • First, agent acts randomly; human compares pairs of video clips and selects the one closer to the objective (e.g., backflip).
  • Algorithm learns a reward function that matches human preferences.
  • Uses RL to optimize agent behavior toward the learned goal.
  • Continually requests human feedback on uncertain trajectory pairs to refine the reward model.
  • High feedback efficiency: backflip task required less than 1000 bits of human feedback.
Originally, RLHF was developed in 2017 by OpenAI, in collaboration with DeepMind, for training simple robots in simulated environments and Atari games. Here, the RL agent starts by acting randomly in the environment. Periodically, two video clips of its behavior are given to a human, and the human decides which of the two clips is closest to the objective: in this case, the objective is to do a backflip. The algorithm gradually builds a model of the goal of the task by finding the reward function that best explains the human’s judgments. It then uses RL to learn how to achieve that goal. As its behavior improves, it continues to ask for human feedback on trajectory pairs where it’s most uncertain about which is better, and further refines its understanding of the goal. This approach is very efficient in terms of human feedback: the backflip video required about 900 bits of human feedback. (In terms of interactions with the environment, it is not cheap: the agent accumulated about 70 hours of simulated experience.)

RLHF

Advantages and drawbacks

Advantage:

  • Compared to offline preference fine-tuning methods such as Direct Preference Optimization (DPO), the Reward Model can score new outputs generated by the policy during training → well-tuned RLHF often performs better with the same human feedback.

Drawbacks:

  • Training can be unstable; the Reward Model may be inaccurate, leading to misaligned or unintended behaviors.
  • The PPO policy may exploit Reward Model weakness (reward hacking).
RLHF has one big advantage for the LLMs usecase: compared to offline preference fine-tuning methods such as Direct Preference Optimization (DPO), which only learn from a fixed dataset of compared answers, the learned Reward Model can score new answers generated by the policy during training. So the same human feedback is exploited further, and well-tuned RLHF with PPO often performs better than DPO (Xu et al., 2024; Ivison et al., 2024). But it also has drawbacks: training can be unstable, and - the Reward Model may be inaccurate, or - the Reward Model may be "exploited" by the policy (reward hacking).

Reasoning-based fine-tuning

Context

  • Many reasoning tasks (math, coding, logic) have answers that can be automatically verified (e.g., final answer check, unit tests).
  • Unlike creative tasks, no human feedback is needed for evaluation.
  • Enables automatic, scalable assessment of LLM outputs.
  • DeepSeek-R1 adds a fine-tuning stage dedicated to reasoning, using RL with verifiable rewards.
There's a special class of NLP problems called reasoning tasks, which includes math, computer science, logic, and so on. Unlike open-ended or creative tasks, many reasoning tasks have an answer that can be checked automatically: for example, comparing the final answer of a math problem with the reference answer, or running unit tests on generated code. This property enables automatic evaluation of LLMs on reasoning tasks, without requiring human feedback for each example. DeepSeek-R1 leverages this by adding a stage of fine-tuning specifically for reasoning, using a Reinforcement Learning framework that exploits verifiable rewards. Note that the overview diagram is a simplification: in practice, the order of the stages varies. DeepSeek-R1 alternates several SFT and RL stages: its first RL stage is dedicated to reasoning, and only its last RL stage also aligns the model with human preferences (helpfulness, harmlessness).

Reinforcement Learning with Verifiable Rewards

So here a reinforcement learning algorithm is used to fine-tune the LLM, using a reward signal that is automatically computed based on whether the final answer is correct or not. The reasoning task fits well within the RL framework: - the policy is the LLM; it generates a sequence of tokens (actions); here we use a stochastic policy, so it outputs a probability distribution over the full vocabulary of tokens at each step; - the state is the current context (prompt + generated tokens) - and the reward is 1 if the final answer is correct, 0 otherwise; it is only given at the end of the generation (all intermediate rewards are 0).

Reasoning-based fine-tuning

Group Relative Policy Optimization (GRPO)

The reinforcement Learning algorithm used in DeepSeek-R1 is called Group Relative Policy Optimization algorithm (or GRPO). It is very similar to PPO, with two differences. First, it uses a different advantage estimation method. The critic network is removed and the advantage is computed by normalizing the returns across a group of episodes. That is to say, for each prompt to assess, multiple rollouts are performed, and the advantage is computed by normalizing the returns of these rollouts. Removing the critic network, which is usually as large as the policy, simplifies the training, speeds it up and saves memory. Second, the KL penalty that keeps the policy close to the reference model is added directly to the loss, instead of being subtracted from the reward as in RLHF with PPO.

DeepSeek-R1-Zero

Results

The DeepSeek-R1-Zero model generated significant attention upon release as the first open LLM fine-tuned exclusively with RL (without supervised fine-tuning) to reach a performance comparable to OpenAI's o1-0912 reasoning model. On AIME 2024, its pass@1 accuracy went from 15.6% to 71.0% during training (86.7% with majority voting), versus 74.4% (83.3%) for o1-0912. It does better on some benchmarks (e.g., MATH-500) and worse on others (e.g., coding). This result highlights the potential of RL-based methods for enhancing reasoning capabilities in large language models.
